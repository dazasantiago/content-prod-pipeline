# topic-deep-research

## Stage contract

`video-orchestrator` launches this stage (①) as an **automatic child session**, only when Santiago asks for
research or the project's format calls for it; it is never run loose. Unlike the other stages it has no
skill: the child runs the CLI and then launches the `research-digest` subagent.

| | |
|---|---|
| **Type** | automatic: it never talks to Santiago |
| **Brief** | project slug and the topic string (plus `--sources youtube` for a concept video) |
| **Reads** | nothing from the pipeline: just the topic string (and optional seed links) |
| **Writes** | `results/<slug>/signals_enriched.json`, `discovered_sources.json`, and (via `research-digest`) `digest.md` |
| **Doesn't** | build the schema, judge the content or call any LLM API |
| **Ends when** | `results/<slug>/digest.md` exists |

The child's final report starts with `ETAPA deep-research · <slug> · <ok|bloqueado> · <path to digest.md>`.

## Purpose

**Scraping-only.** Santiago picks a topic himself and tells Claude to research it — this stage takes
that bare topic string and performs deep content enrichment: timestamped YouTube transcripts with performance numbers and top comments, full article
text via trafilatura (HN/RSS/web), full Reddit threads + comments, and Tavily web discovery for
additional sources. It also accepts a pre-built signal list (legacy `--input` mode, e.g. for a
curated set of seed sources) — see Mode 1 below.

**No LLM API calls. No scoring. No evaluation.** Veracity and recency analysis happen in a
downstream stage.

**Downstream consumer:** as soon as this CLI finishes for a topic, Claude always invokes the
`research-digest` subagent (`.claude/agents/research-digest.md`, en la raíz de `Production/`) before doing anything else with
that topic — it reads `signals_enriched.json` + `discovered_sources.json` and writes a curated
`digest.md` into the same `results/<slug>/` folder. The `contextualizer` stage then walks Santiago through it, and `schema-builder` reads only
`digest.md` (and `context.md`), never the raw JSON directly, to build the video/pieces schema (skill
`schema-builder`, `.claude/skills/schema-builder/SKILL.md`).

---

## Architecture invariants

1. **No LLM API calls.** Pure scraping and HTTP-based search.
2. **No scoring or evaluation.** Roles and signals are preserved as-is.
3. **Isolation.** Does not import from `../automation/`. Reads only the topic input JSON or a topic
   string.
4. **Every enrichment is isolated.** A single failed fetch must never abort the pipeline
   (try/except per unit, returns `fetch_status: "error"` or `"skipped"`).
5. **Only `digest.md` is versioned.** The raw `results/<slug>/*.json` and the `data/*.json` inputs
   are gitignored (they're regenerated by re-running the CLI). **One folder per topic slug** — re-running the same topic overwrites its existing
   `results/<slug>/` folder, there's no week-based versioning.

## Two modes of operation

### Mode 2 (default): `--topic` — discover from scratch

The normal way this stage runs. Santiago names a topic; no upstream artifact is required.
```bash
uv run deep-research --topic "GLM 5.2"
```
See below for details, sources used, and the outlier gate. Mode 1 (`--input`) is documented after it
for the rare case Santiago wants to hand it a specific curated set of sources instead.

### Mode 1: `--input` — pre-classified signals (legacy)

Consumes a JSON file with an already-assembled list of signals under a topic — useful when Santiago
wants to seed the research with specific sources he already found instead of letting it discover on
its own.

```bash
uv run deep-research --input data/<topic-slug>.json
```

Optional flags (both modes):
- `--out-dir <path>` — base output directory (default: `results/`)
- `--top-signals <n>` — max signals to enrich (default: 20)
- `--top-comments <n>` — max comments per post, Reddit and YouTube (default: 10)

**Input shape:**
```json
{
  "topic": "MCP Servers",
  "generated_at": "2026-06-18T12:00:00Z",
  "signals": [ ...Signal[] ]
}
```

**Required fields per signal:**

| Field | Type | Notes |
|---|---|---|
| `source` | string | `"hn"`, `"reddit"`, `"reddit/<sub>"`, `"youtube"`, `"rss"`, `"github_trending"`, etc. |
| `source_id` | string | Unique ID within the source |
| `title` | string | |
| `url` | string \| null | Required for enrichment; no URL → skip |
| `signal_type` | `"signal"` \| `"yt_video"` | `"yt_video"` activates the YouTube transcript enricher |
| `roles` | string[] | See below |
| `metrics` | object | For YouTube in classic mode must include `outlier_ratio` |

**Roles** (metadata from upstream, not used to change scraping behavior):

| Role | Meaning |
|---|---|
| `"signal"` | Primary content source |
| `"validator"` | Corroborates the topic direction |
| `"saturator"` | Indicates topic saturation in this source |

See [`data/example_input.json`](data/example_input.json) for a full example.

### Mode 2 details — discovery sources and flags

Discovers signals from scratch across HN, Reddit, YouTube, and Tavily web, then enriches them
with the same pipeline as Mode 1.

Additional flag:
- `--per-source <n>` — signals to fetch per source (default: 8)
- `--sources <list>` — `all` (default) or a comma-separated subset of `hn`, `youtube`, `x`, `web`
  (Tavily). `--sources youtube` is the light research used for **concept** videos: only YouTube is
  queried, so no X credits and no Tavily search are spent. Topic mode only.

**Sources used for discovery:**

| Source | Implementation | Key required |
|---|---|---|
| HN | Algolia API (`hn.algolia.com/api/v1/search`) | No |
| YouTube | YouTube Data API v3: `search` (twice: most relevant + most viewed, deduplicated), then `videos` and `channels` for the numbers | `YOUTUBE_API_KEY` |
| X | X API v2 full-archive search (`api.x.com/2/tweets/search/all`) | `X_BEARER_TOKEN` |
| Tavily web | Existing `discover_sources()` | `TAVILY_API_KEY` |

Any missing key makes that source silently skip; the others continue.

### YouTube specifics

YouTube is the stage's source for **how other creators structure the topic and how it performed**.
Per run it costs ~200 API quota units (the daily limit is 10 000).

- **Discovery** runs two searches per `--per-source` (relevance, then `viewCount`) and merges them, so
  the result holds both what exists on the topic and what has been watched most. `metrics.found_by`
  says which search surfaced each video.
- **Numbers per video** (`metrics`, descriptive only — no scoring): `view_count`, `like_count`,
  `comment_count`, `duration_s`, `channel_title`, `subscriber_count` (null if hidden),
  `views_per_subscriber`, `age_days`, `views_per_day`, `like_rate`. `views_per_subscriber` is what
  shows a video did well *for its channel*; raw views alone just rank big channels. `views_per_day` is
  a lifetime average, so read it together with `age_days` (a 2018 and a 2025 video aren't comparable).
- **Transcript with timestamps:** `full_text` has one `[MM:SS]` line per 15 s (up to 30 000 chars),
  which is what lets `research-digest` read a video's structure (hook length, where sections change).
- **Chapters** parsed from the description (only if it has a `0:00` line and 3+ entries) go in
  `metadata.chapters`. **Top comments** (`--top-comments`, by relevance) are appended to `full_text`
  under `TOP COMMENTS`.
- **Languages:** transcripts are fetched in English or Spanish; a video with neither comes back
  `skipped` (`NoTranscriptFound`).
- **Library:** `youtube-transcript-api` must be 1.2+. Version 0.6 stopped working (YouTube returns
  empty responses) and every transcript failed silently.

### X specifics

- **Full-archive search works on pay-per-use.** Verified September 2026 against the REST endpoint
  with an App-only Bearer token. The widely-repeated "full archive needs Enterprise" claim is wrong;
  the 7-day limit belongs to `counts/recent`, a different endpoint.
- **`start_time` is always sent explicitly.** Omitting it silently narrows the window to a few days
  and returns an empty result — which reads like a permissions failure but isn't. Default window is
  180 days (`window_days`).
- **Search honours `tweet.fields`**, so `note_tweet` returns the untruncated body right in the
  search response. No hydration round-trip is needed. (The MCP wrapper *does* drop these fields —
  if you test through MCP you'll see truncated 280-char text and conclude otherwise.)
- **No local filtering or ranking.** Same invariant as the rest of the stage: no scoring. Engagement
  lands in `metrics` for `research-digest` to weigh, exactly like HN points. Query quality is the
  user's lever — a broad query like `claude code` returns any passing mention, so search specific
  terms.
- **Cost:** $0.005 per post returned. `max_results` has an API minimum of 10, so the floor is ~$0.05
  per topic regardless of `n`. Empty queries are free.

**Reddit is intentionally excluded from discovery.** `old.reddit.com/search.json` blocks bots
unreliably. Tavily already surfaces the most relevant Reddit threads as `discovered_sources`,
which can then be enriched by `RedditEnricher` in a downstream step if the URL is a direct post
link.

Discovered signals are interleaved (round-robin across sources) before being passed to the
enricher pipeline, so `--top-signals` doesn't eliminate an entire source.

**`--input` and `--topic` are mutually exclusive** — exactly one must be provided.

## Enrichment logic by source

| `source` / `signal_type` | Enricher | What it fetches |
|---|---|---|
| `signal_type == "yt_video"` | `YouTubeEnricher` | Timestamped transcript (up to 30k chars), chapters, top comments; EN or ES |
| `signal_type == "x_post"` | `XEnricher` | The author's own thread, chained onto the root post. Discovery already captured the root's full text, so a standalone post costs no extra call — the enricher only fires when `reply_count > 0`, using `conversation_id:<id> from:<author>` to isolate the author's chain and exclude third-party replies |
| `source == "hn"` | `HNEnricher` (trafilatura) | Full article text + author/date |
| `source.startswith("reddit")` | `RedditEnricher` | Post body + top N comments + timestamps |
| Any other with URL | `HNEnricher` (trafilatura fallback) | Extracted text from URL |

### YouTube outlier gate

In **classic mode** (`--input`), the transcript is fetched only when:
- `outlier_ratio >= 3.0` (clear overperformer), **or**
- `outlier_ratio <= 0.33` (extreme underperformer)

Videos with ratio between 0.34–2.99 → `fetch_status: "skipped"`.

In **topic mode** (`--topic`), discovered YouTube videos carry their own numbers (see "YouTube
specifics") but no `outlier_ratio`. The enricher runs with `force=True`, which **bypasses the gate
entirely** and always attempts to fetch the transcript.

## Web discovery (Tavily)

`discover_sources()` runs on every invocation (both modes) and searches Tavily for additional web
sources on the topic. Results are written to `discovered_sources.json` alongside the enriched
signals. If `TAVILY_API_KEY` is absent, this step is silently skipped and an empty array is
written.

## Output

Written to:
```
results/<topic-slug>/
  signals_enriched.json
  discovered_sources.json
  digest.md            ← written by the research-digest subagent, not this CLI
```

The slug lowercases the topic and replaces non-alphanumeric chars with hyphens (`"MCP Servers"` →
`"mcp-servers"`). There is no week label in the path — one folder per topic, and re-running the same
topic overwrites its existing folder.

**`signals_enriched.json`** — array of `EnrichedSignal`:
```json
{
  "original": { ...full Signal with roles + metrics... },
  "full_text": "Transcript or article...",
  "metadata": { "transcript_segment_count": 312, "video_id": "abc111" },
  "scraped_at": "2026-06-18T13:45:00Z",
  "fetch_status": "ok",
  "fetch_error": null
}
```
`fetch_status`: `"ok"` | `"skipped"` (no error, just not applicable) | `"error"` (fetch failed).

**`discovered_sources.json`** — array of `DiscoveredSource`:
```json
{
  "url": "https://...",
  "domain": "simonwillison.net",
  "title": "...",
  "content": "Extracted text from Tavily...",
  "published_date": "2026-06-15",
  "search_query": "MCP Servers",
  "scraped_at": "2026-06-18T13:45:00Z"
}
```
`published_date` can be `null`.

See [`data/example.output.json`](data/example.output.json) for a full example. A real run writes the
two arrays as **separate files** (`signals_enriched.json` and `discovered_sources.json`); the example
combines them in one documented object under `signals_enriched` / `discovered_sources` keys.

## Environment variables

| Variable | Required | Used by |
|---|---|---|
| `TAVILY_API_KEY` | Optional | Web discovery (`discover_sources`). Without it → empty `discovered_sources.json`, enrichment continues |
| `YOUTUBE_API_KEY` | Optional (topic mode only) | YouTube discovery, numbers and top comments. Without it → YouTube signals skipped, HN/X still run |
| `X_BEARER_TOKEN` | Optional | X full-archive search + thread expansion. App-only Bearer token from the X Developer Portal (not a user token). Without it → X signals skipped entirely. Billed per post returned against prepaid credits |
| `YOUTUBE_COOKIES_FILE` | Optional | Path to a Netscape-format cookies.txt exported from a logged-in browser. Required when YouTube returns 429 rate-limit errors on transcript fetch. Export via the "Get cookies.txt LOCALLY" browser extension. |
